# Design tokens

Tokens for the test bench direction described in [direction.md](direction.md). The colour tokens are daisyUI 5 theme variables plus a small set of app-specific variables prefixed `--qa-`. Everything else (type, spacing, radii, shadows) is a Tailwind extension.

## Before you paste: the Tailwind/daisyUI version situation

The repo runs `daisyui@5` on `tailwindcss@3` (see [audit.md](audit.md) §1.3). daisyUI 5 is built for Tailwind 4 and configured in CSS, so:

- The `daisyui: { themes: [...] }` key in `tailwind.config.ts` is ignored today. Delete it.
- daisyUI 5 themes are plain CSS custom properties, so a theme can be defined as a CSS block in `src/index.css` and selected with `data-theme` on `<html>`. That works on Tailwind 3 now and keeps working after a Tailwind 4 upgrade.
- The colour utilities (`bg-base-100`, `text-base-content`, `bg-primary`, `alert-success`…) are generated by the daisyUI plugin and read those variables. Verified on this repo's toolchain: `bg-base-100` and `text-base-content` compile; `mb-7.5` and `text-2xs` do not.
- The `colors` block in `tailwind.config.ts` currently overrides daisyUI's `primary`, `success`, `warning`, `info` with Bootstrap hex values. Remove those four so daisyUI's variable-based utilities win; keep the legacy-only names (`danger`, `muted`, `light`, `dark`, `border`, `primary-dark`) as aliases to variables until the stage sweep removes them.

Upgrading to Tailwind 4 is optional and not required by this design. If it happens, the theme block below converts one to one into `@plugin "daisyui/theme" { … }` (shown at the end).

### The veil pattern

The shielded hatch is a token, not an ad-hoc gradient:

```css
--qa-veil: repeating-linear-gradient(
  135deg,
  color-mix(in oklab, var(--color-accent) 22%, transparent) 0 2px,
  transparent 2px 6px
);
```

Used for: the Shielded testnet rail, the dot inside the Shielded testnet chip, hidden-amount pills, and the left edge of shielded output rows. Nowhere else.

## Typography

| Token | Size / line height | Family | Weight | Use |
|---|---|---|---|---|
| `text-caption` | 12 / 16 | sans | 400 | Help text, timestamps, table footers |
| `text-body` | 14 / 20 | sans | 400 | Default UI text, labels (500) |
| `text-body-lg` | 16 / 24 | sans | 400 | Prose blocks: walkthrough instructions, setup guides (max 65ch) |
| `text-title-sm` | 18 / 26 | sans | 600 | Panel titles |
| `text-title` | 21 / 28 | sans | 600 | Rarely: dialog titles |
| `text-page` | 24 / 32 | sans | 700 | Stage title (one per page) |
| `text-data` | 13 / 20 | mono | 400 | Hashes, addresses, amounts, JSON, method names |
| `text-data-sm` | 12 / 16 | mono | 400 | Dense tables, chips containing data |

Families:

- `font-sans`: `"Atkinson Hyperlegible Next", system-ui, -apple-system, "Segoe UI", sans-serif`
- `font-mono`: `"JetBrains Mono", ui-monospace, "SFMono-Regular", monospace`, with `font-feature-settings: "zero" 1` and `font-variant-numeric: tabular-nums`

Self-host Atkinson Hyperlegible Next the same way JetBrains Mono is today (files in `public/fonts/` with `@font-face`), or through the Fontsource package; check the package name on npm before adding it. Weights needed: 400, 500, 600, 700.

No uppercase, no letter-spacing, on any label.

## Spacing

4px grid (Tailwind's default `1` = 4px). Named usage so stages stop guessing:

| Purpose | Value | Tailwind |
|---|---|---|
| Inside a chip or badge | 4px × 8px | `py-1 px-2` |
| Between a label and its field | 6px | `gap-1.5` |
| Between fields in a form | 12px | `gap-3` |
| Panel padding | 16px (20px ≥1280px) | `p-4 xl:p-5` |
| Between sections inside a panel | 20px with a hairline rule | `gap-5` + `border-t` |
| Between panels in a stage | 16px | parent `flex flex-col gap-4` |
| Stage content padding | 24px (16px on phones) | `p-4 md:p-6` |

Stack spacing comes from the parent (`gap-*`), never from `mb-*` on children. That is what made the broken `mb-7.5` possible in the first place.

Control sizes: fields and buttons 36px (`--size-field: 0.225rem` gives daisyUI's `calc(var(--size-field) * 10)`), small buttons 28px, sidebar rows 32px, table rows 36px, top bar 48px.

## Radii

Radius encodes hierarchy instead of being the same everywhere:

| Element | Radius |
|---|---|
| Panels, dialogs, popovers | 6px (`--radius-box`) |
| Fields, buttons, segmented controls | 4px (`--radius-field`) |
| Checkboxes, small badges | 3px (`--radius-selector`) |
| Status chips, network chip, server pill | full (`rounded-full`) |
| The network rail, tables | 0 |

## Elevation and shadow

Flat by default (`--depth: 0`, `--noise: 0`). Panels get a 1px `base-300` border and no shadow. A single shadow token exists for things floating over content (menus, command palette, toasts, dialogs):

```css
--qa-shadow-float: 0 10px 28px -8px rgb(16 20 30 / 0.22), 0 2px 6px -2px rgb(16 20 30 / 0.14);
```

Focus ring: 2px `primary` outline with 2px offset, via `:focus-visible`, on every interactive element. Never remove it.

## Motion

- 120ms ease-out for hover and press, 180ms for disclosure (accordion, popover).
- One continuous animation is allowed: the in-progress status dot. Under `prefers-reduced-motion: reduce` it becomes a static half-filled ring.
- No entrance animations on stage content.

Note: `primary`, `success`, `warning`, `info` are intentionally absent from `colors` so daisyUI's own utilities (which read the theme variables) are used. The six legacy call sites that use opacity modifiers on those colours (`bg-primary/10` ×3, `bg-success/10`, `bg-warning/10`, `bg-danger/10`) should switch to the `tint-*` colours, because Tailwind 3 cannot apply `/<alpha>` to a CSS-variable colour.

### 3. Same theme on Tailwind 4 (only if you upgrade)

```css
@import 'tailwindcss';
@plugin "daisyui" { themes: false; }
@plugin "daisyui/theme" {
  name: 'bench';
  default: true;
  color-scheme: light;
  --color-base-100: #ffffff;
  /* …same variables as the [data-theme='bench'] block… */
}
@plugin "daisyui/theme" {
  name: 'bench-dark';
  prefersdark: true;
  color-scheme: dark;
  --color-base-100: #1c1f26;
  /* …same variables as the [data-theme='bench-dark'] block… */
}
@theme {
  --font-sans: 'Atkinson Hyperlegible Next', system-ui, sans-serif;
  --font-mono: 'JetBrains Mono', ui-monospace, monospace;
  --color-net-testnet: var(--qa-net-testnet);
  --color-net-shielded: var(--qa-net-shielded);
  --color-net-mainnet: var(--qa-net-mainnet);
  /* …and the font sizes above as --text-* */
}
```

App variables (`--qa-*`) stay in a plain `[data-theme]` block either way, because daisyUI's theme plugin only accepts its own variable names.
